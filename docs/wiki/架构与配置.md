# 架构与配置

面向想深入了解或做二次开发的读者：技术架构、一次请求的生命周期、数据面接口、配置项与部署形态。

---

## 技术架构

- **后端**：Rust（axum）单进程单二进制，全内存热路径 + 异步落库，默认零外部依赖。
- **前端**：React + Vite 双应用（门户 / 后台），静态资源随二进制分发；图表统一 ECharts。
- **存储**：SQLite（默认，单文件）或 PostgreSQL；**缓存**：进程内（默认）或 Redis（多实例共享）。
- **链路日志**：SQLite / Elasticsearch 双后端可选，保留期自动清理。
- **配置体系**：`config/default.toml` + 环境变量覆盖（前缀 `RELAY_`，`__` 分隔层级）；供应商/模型/模型组/路由/奖励任务全部由后台维护并持久化到数据库，不需要改配置文件。

```
                    ┌──────────────────────── Relay 单进程 ────────────────────────┐
客户端 SDK ────────▶│ 鉴权 → 限流 → 路由选择 → 语义缓存 → 协议互转 → 上游转发        │──▶ OpenAI / Anthropic / DeepSeek / 通义 / 智谱 / 私有部署 …
门户 / 后台 ───────▶│ (failover + 熔断) → 计费扣减 → 异步落库(链路/用量/审计)        │
                    └─────── SQLite / PostgreSQL ───────── Redis(可选) ────────────┘
```

## 一次请求的生命周期

1. **鉴权**：`Authorization: Bearer rk_live_...` → 定位用户与模型组（内存完成）；
2. **校验与限流**：入站 payload 校验、并发槽、RPM/TPM 限流（超限 429 结构化响应）；
3. **路由选择**：按对外模型名找到模型组内所有路由，按策略（加权/优先级/成本/延迟优先）排出候选顺序；
4. **语义缓存**（若路由开启）：L1 精确 → L2 embedding 相似度；命中按折扣率计费直接返回；
5. **协议互转与转发**：客户端协议与上游协议不一致时逐 chunk 回译（含工具调用与图片）；
6. **故障转移**：连接失败/超时/429/5xx 自动切下一候选；连续失败熔断、半开探测恢复；
7. **计费**：按 tokens × 单价 × 倍率扣减余额，日/月预算耗尽拒绝；
8. **异步落库**：链路（候选链/请求响应预览）、用量明细、审计——不阻塞响应主路径。

## 数据面接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/healthz` | 健康检查（返回版本号） |
| GET | `/v1/models` | 当前用户可见的对外模型列表（按组隔离） |
| POST | `/v1/chat/completions` | OpenAI Chat Completions，流式 / 非流式 |
| POST | `/v1/responses` | OpenAI Responses 协议转发 |
| POST | `/v1/messages` | Anthropic Messages，流式 / 非流式 |
| POST | `/v1/embeddings` | OpenAI 兼容 embeddings 转发 |
| GET | `/metrics` | Prometheus 指标导出（管理端 JWT 或 `metrics.export_token` 鉴权） |

完整参数、错误码与示例代码见后台/门户内置 **API 文档页**。

## 配置项

**四层优先级（高 → 低，高层存在时覆盖低层）**：

| 层 | 载体 | 适用 | 生效时机 |
|---|---|---|---|
| ④ 数据库 `settings` 表 | 后台「设置」页 / 内部自动生成 | 邮箱、缓存、日志、管理员密码、自动生成的 JWT 密钥等运行时可调项 | 热生效（或重启后） |
| ③ 环境变量 `RELAY_*` | `relay.env`（systemd）/ compose environment / export | **部署差异项与敏感项**：端口、数据库、Redis、管理员口令、SMTP 授权码 | 重启后 |
| ② `config/default.toml` | 安装目录内配置文件 | 全量参数与默认值（有注释，首次安装写入、升级不覆盖） | 重启后 |
| ① 代码内置默认值 | — | 兜底 | — |

**怎么选**：端口/数据库/管理员口令等部署差异 → `relay.env`；临时调优与运营参数 → 直接后台「设置」页；两者都别写的项用 `default.toml` 默认值即可。同一 key 多层都写了时以高层为准（环境变量没生效，先查是不是被 DB 层或变量名层级写错——层级分隔是双下划线 `__`）。

### 配置清单：改哪里、什么时候生效

**安装前（可选预配置）**：改包内 `config/default.toml` 再执行 install.sh（首次安装原样拷入，升级不覆盖已存在的配置）；或先装完再写 `relay.env` + 重启。唯一建议**首启前定死**的是数据库类型（`[database]`，建表随首启完成，事后 SQLite↔PG 切换需自行迁移数据）；端口/目录装完改也很方便。

**安装后**（后台 UI 全部热生效；env/toml 改完 `relay restart`）：

| 配置 | 默认值 | 安装后改哪里 | 生效 |
|---|---|---|---|
| 监听端口 | 8080 | `relay port 9000`（写 relay.env + 自动重启） | 重启 |
| 数据库 | SQLite(relay.db) | relay.env `RELAY_DATABASE__*` | 重启 |
| 缓存后端 | memory | relay.env `RELAY_CACHE__*` | 重启 |
| JWT 密钥 | 首启自动生成 | 无需配置（显式 `RELAY_AUTH__JWT_SECRET` 优先） | 重启 |
| 会话时长 | 7 天 | `RELAY_AUTH__SESSION_TTL_SECS` | 重启 |
| 管理员密码 | admin / Relay@123 | 后台「设置 → 管理员账号」（热）/ env（重启） | 即时 |
| SMTP 邮件 | 空=开发模式 | 后台「设置 → 邮箱配置」（带发信测试） | 即时 |
| 全局并发槽 | 16 | `RELAY_DEFAULTS__CONCURRENCY_LIMIT` | 重启 |
| 注册赠送 | 1,000,000 tokens | `RELAY_DEFAULTS__SIGNUP_GRANT_TOKENS` | 重启 |
| RPM/TPM 默认上限 | 0（不限） | `RELAY_DEFAULTS__RPM_LIMIT` / `__TPM_LIMIT` | 重启 |
| 上游并发默认 | 32 | `RELAY_DEFAULTS__UPSTREAM_CONCURRENCY` | 重启 |
| 时段规则时区 | Asia/Shanghai | `RELAY_DEFAULTS__TIMEZONE` | 重启 |
| 容错/重试 | 开 / 5 次 | 后台「设置 → 容错与降级」 | 即时 |
| 语义缓存 | 关 | 后台「设置 → 语义缓存」 | 即时 |
| L2 向量(embedding) | 未配置 | 后台「设置 → 语义向量」 | 即时 |
| 链路日志 | SQLite / 预览 8KB / 留 30 天 | 后台「设置 → 日志」（ES 后端走 `RELAY_LOGGING__*`） | 即时 |
| 门户奖励开关 | 关 | 后台「设置 → 门户设置」 | 即时 |
| /metrics 令牌 | 空（仅 admin JWT 可读） | `RELAY_METRICS__EXPORT_TOKEN` | 重启 |
| 转发超时 | 非流式 300s / 连接 10s | `RELAY_PROXY__UPSTREAM_TIMEOUT_SECS` / `__CONNECT_TIMEOUT_SECS` | 重启 |
| 供应商/模型/模型组/路由/时段/奖励任务 | 空 | 后台对应页面 | 即时 |

> 口诀：**带"重启"的都在 env/toml，后台设置页全热生效**。改完用 `relay info` 看当前值、`relay restart` + `relay health` 验证。

环境变量示例：

```bash
RELAY_SERVER__BIND=0.0.0.0:9000
RELAY_AUTH__JWT_SECRET=your-secret
RELAY_ADMIN__PASSWORD=your-admin-password
RELAY_DATABASE__TYPE=postgres
```

| 配置段 | 说明 |
|---|---|
| `[server]` | 监听地址 |
| `[database]` | `sqlite`（默认）或 `postgres`（分项或完整 url） |
| `[cache]` | `memory`（默认）或 `redis`（多实例共享） |
| `[auth]` / `[admin]` | JWT 密钥缺失/弱值时首启自动生成（存 DB）；管理员口令建议环境变量引导，登录后在后台「设置 → 管理员账号」改密 |
| `[email]` | 注册验证码 SMTP；留空为开发模式（验证码打日志并随响应返回） |
| `[defaults]` | 全局默认限额：并发槽、新用户注册赠送 token |
| `[proxy]` | 转发超时：非流式总超时 / 连接超时；流式不设总超时 |
| `[logging]` | 链路日志后端、正文预览上限（0=不采集）、保留天数（0=永久，默认 30 天） |
| `[metrics]` | `/metrics` 导出令牌 |

> `[proxy]` 与 `[metrics]` 为内置默认值，按需用环境变量覆盖即可。

## 部署形态

| 形态 | 数据库 | 缓存 | 链路日志 | 适用场景 |
|---|---|---|---|---|
| **All-in-One（默认）** | SQLite | 进程内 | SQLite | 自用 / 小规模，零外部依赖 |
| **生产** | PostgreSQL | Redis（可选） | Elasticsearch（多实例日志检索；单实例也可用 SQLite） | 多实例 / 高并发 / 日志检索 |

多实例横向扩展：共享 PostgreSQL（数据）与 Redis（缓存）即可。安装与升级的完整流程见 [安装与升级](https://github.com/stoneaigc/Relay/wiki/安装与升级)，反向代理见 [Nginx 反向代理](https://github.com/stoneaigc/Relay/wiki/Nginx-反向代理)。

**生产检查清单**：

- [ ] `RELAY_AUTH__JWT_SECRET` 换长随机串；`RELAY_ADMIN__USERNAME/PASSWORD` 覆盖默认口令（在线安装自动生成）
- [ ] 敏感变量统一写入 `/opt/relay/relay.env`（systemd）或 compose environment（Docker）
- [ ] 反向代理终结 TLS；`/metrics` 仅对内网暴露或配置导出令牌
- [ ] 统一登录 `/login` 与 `/api/auth/login` 会对外暴露管理端登录面（自带防爆破）：不需要公共入口时可在反向代理中限制来源或仅保留 `/admin/`、`/portal/` 直达路径
- [ ] 数据备份计划（SQLite 库文件 / `pg_dump`）
- [ ] 按需配置 `RELAY_EMAIL__SMTP_*`

## 性能基准

内置零依赖基准脚本（内嵌零延迟 mock 上游，数字代表网关自身开销）：

```bash
node scripts/bench.mjs --key rk_live_xxx [--base http://localhost:8080] [--duration 10] [--concurrency 16]
```

参考数字（release build，`--duration 10 --concurrency 16`，Windows 11 桌面机，仅供横向参考）：

| 场景 | RPS | avg | P50 | P95 | 错误 |
|---|---|---|---|---|---|
| `GET /healthz`（纯 HTTP 栈） | ~9900 | 1.6ms | 1.3ms | 3.1ms | 0 |
| `GET /v1/models`（内存鉴权） | ~9600 | 1.7ms | 1.5ms | 3.0ms | 0 |
| `POST /v1/chat/completions`（全链路） | ~720 | 22ms | 4.4ms | 7.7ms | 0 |

chat 为语义缓存全未命中重路径，P50 仍在 5ms 内；持续 4 万+ 请求后进程内存 ≈ 29MB。

## 版本与升级机制

- 版本号贯穿前后端：启动日志、`/healthz` JSON、后台侧边栏与「设置 → 软件更新」均展示当前版本；
- 升级通道：`upgrade.sh` 一键升级（自动备份可回滚）/ 后台检查更新 / 手动覆盖安装 / Docker pull，详见 [安装与升级 · 升级](https://github.com/stoneaigc/Relay/wiki/安装与升级#升级)；
- Release 由 CI 自动构建（x86_64 / arm64 musl 静态），Release Notes 取自 `CHANGELOG.md` 对应章节。
