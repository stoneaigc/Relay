# 架构与配置

面向想深入了解或做二次开发的读者：技术架构、一次请求的生命周期、数据面接口、配置项与部署形态。

---

## 技术架构

- **后端**：Rust（axum）单进程单二进制，全内存热路径 + 异步落库，默认零外部依赖。
- **前端**：React + Vite 双应用（门户 / 后台），静态资源随二进制分发；图表统一 ECharts。
- **存储**：SQLite（默认，单文件）或 PostgreSQL；**缓存**：进程内（默认）或 Redis（多实例共享）。
- **链路日志**：SQLite / PostgreSQL / Elasticsearch 三后端可选，保留期自动清理。
- **配置体系**：`config/default.toml` + 环境变量覆盖（前缀 `RELAY_`，`__` 分隔层级）；供应商/模型/模型组/路由/奖励任务全部由后台维护并持久化到数据库，不需要改配置文件。

```
                    ┌──────────────────────── Relay 单进程 ────────────────────────┐
客户端 SDK ────────▶│ 鉴权 → 限流 → 路由选择 → 语义缓存 → 协议互转 → 上游转发        │──▶ OpenAI / Anthropic / DeepSeek / 通义 / 智谱 / 私有部署 …
门户 / 后台 ───────▶│ (failover + 熔断) → 计费扣减 → 异步落库(链路/用量/审计)        │
                    └─────── SQLite / PostgreSQL ───────── Redis(可选) ────────────┘
```

## 一次请求的生命周期

1. **鉴权**：`Authorization: Bearer rk_live_...` → 定位用户与模型组（内存完成）；
2. **校验与限流**：入站 payload 校验、并发槽、RPM/TPM 限流（超限 429 结构化响应）；
3. **路由选择**：按对外模型名找到模型组内所有路由，按策略（加权/优先级/成本/延迟优先）排出候选顺序；
4. **语义缓存**（若路由开启）：L1 精确 → L2 embedding 相似度；命中按折扣率计费直接返回；
5. **协议互转与转发**：客户端协议与上游协议不一致时逐 chunk 回译（含工具调用与图片）；
6. **故障转移**：连接失败/超时/429/5xx 自动切下一候选；连续失败熔断、半开探测恢复；
7. **计费**：按 tokens × 单价 × 倍率扣减余额，日/月预算耗尽拒绝；
8. **异步落库**：链路（候选链/请求响应预览）、用量明细、审计——不阻塞响应主路径。

## 数据面接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/healthz` | 健康检查（返回版本号） |
| GET | `/v1/models` | 当前用户可见的对外模型列表（按组隔离） |
| POST | `/v1/chat/completions` | OpenAI Chat Completions，流式 / 非流式 |
| POST | `/v1/responses` | OpenAI Responses 协议转发 |
| POST | `/v1/messages` | Anthropic Messages，流式 / 非流式 |
| POST | `/v1/embeddings` | OpenAI 兼容 embeddings 转发 |
| GET | `/metrics` | Prometheus 指标导出（管理端 JWT 或 `metrics.export_token` 鉴权） |

完整参数、错误码与示例代码见后台/门户内置 **API 文档页**。

## 配置项

环境变量示例：

```bash
RELAY_SERVER__BIND=0.0.0.0:9000
RELAY_AUTH__JWT_SECRET=your-secret
RELAY_ADMIN__PASSWORD=your-admin-password
RELAY_DATABASE__TYPE=postgres
```

| 配置段 | 说明 |
|---|---|
| `[server]` | 监听地址 |
| `[database]` | `sqlite`（默认）或 `postgres`（分项或完整 url） |
| `[cache]` | `memory`（默认）或 `redis`（多实例共享） |
| `[auth]` / `[admin]` | JWT 密钥与后台凭据，生产必须覆盖 |
| `[email]` | 注册验证码 SMTP；留空为开发模式（验证码打日志并随响应返回） |
| `[defaults]` | 全局默认限额：并发槽、新用户注册赠送 token |
| `[proxy]` | 转发超时：非流式总超时 / 连接超时；流式不设总超时 |
| `[logging]` | 链路日志后端、正文预览上限（0=不采集）、保留天数（0=永久，默认 30 天） |
| `[metrics]` | `/metrics` 导出令牌 |

> `[proxy]` 与 `[metrics]` 为内置默认值，按需用环境变量覆盖即可。

## 部署形态

| 形态 | 数据库 | 缓存 | 链路日志 | 适用场景 |
|---|---|---|---|---|
| **All-in-One（默认）** | SQLite | 进程内 | SQLite | 自用 / 小规模，零外部依赖 |
| **生产** | PostgreSQL | Redis（可选） | PostgreSQL 或 Elasticsearch | 多实例 / 高并发 / 日志检索 |

多实例横向扩展：共享 PostgreSQL（数据）与 Redis（缓存）即可。安装与升级的完整流程见 [安装与升级](安装与升级)，反向代理见 [Nginx 反向代理](Nginx-反向代理)。

**生产检查清单**：

- [ ] `RELAY_AUTH__JWT_SECRET` 换长随机串；`RELAY_ADMIN__USERNAME/PASSWORD` 覆盖默认口令（在线安装自动生成）
- [ ] 敏感变量统一写入 `/opt/relay/relay.env`（systemd）或 compose environment（Docker）
- [ ] 反向代理终结 TLS；`/metrics` 仅对内网暴露或配置导出令牌
- [ ] 数据备份计划（SQLite 库文件 / `pg_dump`）
- [ ] 按需配置 `RELAY_EMAIL__SMTP_*`

## 性能基准

内置零依赖基准脚本（内嵌零延迟 mock 上游，数字代表网关自身开销）：

```bash
node scripts/bench.mjs --key rk_live_xxx [--base http://localhost:8080] [--duration 10] [--concurrency 16]
```

参考数字（release build，`--duration 10 --concurrency 16`，Windows 11 桌面机，仅供横向参考）：

| 场景 | RPS | avg | P50 | P95 | 错误 |
|---|---|---|---|---|---|
| `GET /healthz`（纯 HTTP 栈） | ~9900 | 1.6ms | 1.3ms | 3.1ms | 0 |
| `GET /v1/models`（内存鉴权） | ~9600 | 1.7ms | 1.5ms | 3.0ms | 0 |
| `POST /v1/chat/completions`（全链路） | ~720 | 22ms | 4.4ms | 7.7ms | 0 |

chat 为语义缓存全未命中重路径，P50 仍在 5ms 内；持续 4 万+ 请求后进程内存 ≈ 29MB。

## 版本与升级机制

- 版本号贯穿前后端：启动日志、`/healthz` JSON、后台侧边栏与「设置 → 软件更新」均展示当前版本；
- 升级通道：`upgrade.sh` 一键升级（自动备份可回滚）/ 后台检查更新 / 手动覆盖安装 / Docker pull，详见 [安装与升级 · 升级](安装与升级#升级)；
- Release 由 CI 自动构建（x86_64 / arm64 musl 静态），Release Notes 取自 `CHANGELOG.md` 对应章节。
