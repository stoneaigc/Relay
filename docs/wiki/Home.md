# Relay · LLM API 转发网关

> **单进程 Rust 二进制**。对外同时兼容 **OpenAI** 与 **Anthropic** 协议，对内接入任意多家供应商——智能路由、协议互转、故障转移、语义缓存、计费管控、全链路追踪；自带**用户门户**与**运营后台**，默认零外部依赖。

主仓库与 Release：<https://github.com/stoneaigc/Relay>

## 它解决什么问题

接入多家模型供应商时，团队通常会撞上同一批问题：不同供应商协议不一致、某家挂了业务就断、用量和成本说不清、给外部发 Key 之后更是黑盒。Relay 把这些收敛成一个入口：

```
客户端 SDK ──▶ Relay 网关 ──▶ OpenAI / Anthropic / DeepSeek / 通义 / 智谱 / 私有部署 …
门户用户  ──▶ (鉴权 → 路由 → 协议互转 → 故障转移 → 计费 → 链路追踪)
运营后台 ──▶
```

**一句话定位：面向个人开发者与中小团队的自托管 LLM API 网关**——把任意多家模型供应商收敛成一个 OpenAI / Anthropic 兼容入口，且天生自带「运营」属性：发 Key、计费、限流、审计、门户，开箱即用。

## 核心能力

### 转发核心

- **双协议入站**：`/v1/chat/completions`（OpenAI）与 `/v1/messages`（Anthropic），流式 / 非流式，支持工具调用与多模态图片。
- **协议互转**：上游是 OpenAI 还是 Anthropic 都透明路由，流式逐 chunk 回译——客户端用哪套协议、上游是什么协议，互不约束。
- **智能路由**：一个对外模型名映射多个上游；加权随机 / 加权轮询 / 轮询 / 优先级 / 成本优先 / 延迟优先（P50）六种负载策略。
- **故障转移 + 熔断**：连接失败 / 超时 / 429 / 5xx 自动切换下一候选；连续失败熔断、半开探测自动恢复。
- **语义缓存**：L1 精确命中 + L2 embedding 相似度命中，路由级开关、仅缓存确定性请求、命中折扣率可配、`no-cache` 逃生口。

### 计费与运营

- **计费管控**：token 计费、模型/用户级倍率热更新、日/月预算（耗尽返回 429）、RPM/TPM 限流、并发槽。
- **用户门户**：邮箱验证码注册/登录/找回、API Key 创建与轮换（明文仅展示一次）、余额与用量、在线对话、模型广场、奖励申领。
- **运营后台**：用户与额度管理、供应商/模型/模型组/路由维护、奖励任务配置与审核、操作审计、SMTP 页面化配置、内置 API 文档页。

### 可观测与安全

- **请求链路追踪**：每次请求完整记录候选顺序、failover 链、熔断跳过、tokens 与请求/响应体预览；链路日志支持 SQLite / PostgreSQL / Elasticsearch 三后端，保留期自动清理。
- **指标**：仪表盘（ECharts）+ Prometheus `GET /metrics` 导出，可直接接入 Grafana。
- **安全**：登录防爆破（三入口滑动窗口）、入站 payload 校验、上游错误统一脱敏、全局 401 踢回登录。
