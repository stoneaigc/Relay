# 功能介绍 · 管理后台

入口：`http://<IP>:<端口>/admin/`。面向**运营者**，负责用户运营、模型接入、路由编排、流量观测与系统配置。左侧导航分五组，逐页说明如下。

---

## 概览

全站仪表盘，进入后台第一眼看到的东西：

- **核心指标卡**：今日请求量、成功率、Tokens 吞吐、活跃用户等关键数字。
- **时序图表（ECharts）**：请求量与调用走势（柱线组合）、延迟分位（P50/P95）、TPM 双轴趋势、缓存命中趋势（命中/未命中堆叠）。
- **用量分布**：横向条形图展示费用与调用量按模型/用户的分布，Top 1 高亮、带百分比 tooltip。
- **上游健康一览**：各供应商当前状态（健康 / 有失败 / 异常 / 熔断中 / 无请求）。

## 运营

### 用户管理

- 创建 / 编辑 / 禁用 / 删除用户，设置初始额度与用户级倍率。
- **绑定模型组**：决定该用户可见且仅可见哪一组模型——这是 Relay 的模型隔离机制。
- 日 / 月预算控制：预算耗尽的用户调用会被拒（429 `insufficient_quota`）。
- 每个用户可展开**用量趋势弹窗**，单独看他的请求、tokens、费用走势。

### 奖励审核

用户在门户提交的奖励申领在这里处理：查看申领详情，**通过 / 驳回**，通过后额度自动入账。

### 奖励设置

配置奖励任务（拉新、实名、首充等自定义任务）：名称、描述、奖励 token 数、开关。用户门户据此展示可申领任务。首次安装已自动播种 3 个示例任务，可直接改。

## 模型与上游

### 上游模型

接入供应商的地方：

- **添加上游**：填协议类型（OpenAI / Anthropic）、Base URL、密钥，自带**模型列表探测**与**连接测试**——填完立刻知道能不能通。
- **勾选模型批量接入**：探测出的模型列表勾选即接入，可顺带批量填输入/输出单价。
- 每个模型可维护：对外展示名、上游真实模型名、单价、上下文长度、标签（用于门户模型广场筛选）。

### 模型组

路由编排的核心，也是「对外模型名」的来源：

- **新建模型组** → **添加路由**：对外模型名 → 实际上游模型，同一对外名可挂多条路由形成主备/负载池。
- 每条路由可设**倍率**（计费系数）与**负载策略**（加权随机/加权轮询/轮询/优先级/成本优先/延迟优先）。
- 支持**路由批量编辑**与**整个模型组 JSON 导入导出**，方便批量迁移与备份。
- 语义缓存按路由开关（默认关）。

## 监控

### 上游治理

所有上游的实时健康面板：每家供应商当前状态、最近错误、熔断状态（连续失败自动熔断、半开探测恢复）。排查「为什么这个模型最近总失败」从这里开始。

### 接口指标

数据面实时流量视图（ECharts）：请求量、成功率、延迟分位、TPM 吞吐、按协议/模型的调用分布。需要接入 Prometheus + Grafana 时，`GET /metrics` 提供文本格式导出。

### 请求链路

Relay 的**亮点功能**——每一次 API 调用的完整留痕，展开任意一条可看到：

- **候选顺序**：负载策略命中后的上游排序与权重；
- **实际尝试链**：每一跳的状态、延迟、错误，含熔断跳过标记——为什么走这条路由、失败切到了哪，一目了然；
- **Tokens 与计费**：输入/输出/计费 tokens、是否流式、费用；
- **请求/响应体预览**：按上限截断存储，便于复盘 prompt（默认 8192 字节、保留 30 天，均可在配置中调整，超期自动清理）。

失败请求自动标红。链路日志支持 SQLite / PostgreSQL / Elasticsearch 三种后端。

### 语义缓存

缓存命中概览与趋势（命中/未命中堆叠图）。缓存机制：L1 精确命中 + L2 embedding 相似度命中，仅缓存确定性请求（temperature=0 或带 seed），命中按折扣率计费，调用方请求头 `no-cache` 可强制绕过。

### 全局用量

全站账单视角：按时间范围查看请求量、tokens、费用，支持按模型 / 用户维度横向条形分布，明细表含时间、耗时、缓存状态等字段。

### 操作审计

管理后台的所有敏感操作（增删改用户/上游/路由等）全部留痕：谁、什么时候、做了什么。出问题可追溯。

## 系统

### API 文档

后台内置的数据面文档：协议端点（OpenAI / Anthropic）、鉴权方式、流式调用、错误码、Prometheus 指标说明，curl / Python / Node 示例一键复制。发给对接方照抄即可。

### 设置

- **SMTP 配置**：页面化配置发件邮箱，用于门户注册/找回密码的验证码邮件（留空则开发模式：验证码打日志）。
- **软件更新**：显示当前版本徽章（与侧边栏底部 `Relay v{版本}` 一致），一键「检查更新」——比对 GitHub 最新 Release，发现新版本给出链接与升级指引（离线或私有仓库时优雅降级提示）。

> 管理员账号密码通过 `/opt/relay/relay.env` 的 `RELAY_ADMIN__USERNAME` / `RELAY_ADMIN__PASSWORD` 配置，修改后重启服务生效。
