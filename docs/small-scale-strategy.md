# 小规模阶段的商业模式与合规路径(决策记录)

> 目标客户:**个人开发者 + 小型团队**。部署:境外服务器 + 境外域名(不办 ICP 备案)。
> 定价区间:99 / 199 / 299 元三档(额度 + 模型权限)。
> 本文记录「小规模试水阶段该走哪条路」的结论与依据,供后续对照执行。

---

## 一、核心结论

**小规模阶段的真正矛盾,不是"选哪种盈利模式",而是「L0 额度差价在小规模下养不活合规成本」。**

算一笔账:

- 99 元档按正规货源毛利 22% 计算,单用户月毛利约 **21.8 元**;
- 合规的起步动作(境内主体 + 大模型登记 + 算法备案 + 服务协议 + 内容审核)保守估 1~2 万元;
- 需要 **500~900 单**才覆盖一次性合规成本,还没算持续运营成本。

而 BYOK 托管按 5% 抽成:一个自带 key 的小团队月消耗 ¥2,000 左右,抽成 ¥100/月,
**单客户年贡献约 ¥1,200,且上游成本为零、不占资金池、不承担封号风险**。

**推荐:以 BYOK 托管 + 能力分层为主要收入,额度套餐降级为获客入口,不做主要利润来源。**

## 二、三条合规红线的性质完全不同

| 红线 | 触发条件 | 小规模下状态 | 说明 |
|---|---|---|---|
| **刑事 · 非法经营罪** | 货源违规(账号池 / 逆向接口 / 拆单绕过限额)+ 经营数额 ≥500 万或违法所得 ≥10 万 | **可规避** | 只要货源干净、规模小,基本不触发。这是唯一一条完全由自己掌控的 |
| **网信 · 大模型登记 + 算法备案** | 向境内公众提供生成式 AI 服务(含通过 API 提供) | **已触发** | 境外部署不免责(办法第 20 条有专门处置条款)。**个人身份办不了**,必须境内独立法人企业 |
| **电信 · ICP 经营许可证** | 通过互联网向用户提供有偿信息服务,**判定看"经营性"不看规模** | **概率性** | 实务上由投诉、举报、专项整治驱动 |

### 几个反直觉但必须记住的点

1. **规模小不是豁免,反而可能落到更重的罚款区间。**
   未取得许可擅自经营的:有违法所得的,没收并处 3~5 倍罚款;
   **没有违法所得或不足 5 万元的,直接处 10 万~100 万元罚款**。
   (依据《互联网信息服务管理办法》第十九条;《电信条例》对应条款门槛为 10 万元,实务需结合业务定性适用。)

2. **已落地的真实处罚**:2026 年 6 月安徽省通信管理局皖通罚决〔2026〕3 号——
   某公司无证经营电信业务,**没收违法所得 ¥112,900 + 罚款 ¥5,000**。
   注意重点不是罚款额,而是「违法所得被全部没收」。

3. **生成式 AI 这条躲不掉,但有低成本通道。**
   备案主体必须是境内独立法人,**自然人、个体工商户均无法提交**。
   但调用第三方已备案大模型(本项目的形态)走**生成式服务登记**简化通道:
   省级网信办审核,周期 1~2 个月,材料轻(登记表、服务协议、基础资质)。
   自研/微调模型才需要完整备案:省初审 + 国家网信办终审,3~6 个月,材料 30~100 页。

4. **已有同类被处置案例**:2026 年 3 月无锡某公司通过 API 调用已备案大模型向用户提供服务,
   未履行登记、未开展安全评估,被约谈并责令下线。**主动补办从轻,被查到是暂停+处罚**。

5. **2026 年监管态势已变**:中央网信办 4 月启动「清朗·整治 AI 应用乱象」专项行动,
   第一阶段处置违规 AI 产品 1.4 万余款,**「未按规定履行大模型备案登记义务」被列为头号整治问题**。

## 三、本项目当前的两个具体缺口

### 缺口 1:响应改写可能影响「登记 vs 备案」的定性(需提前确认)

`src/handlers.rs` 中存在协议层改写:

- 第 1813 行附近:Anthropic 事件透传后做 **JSON 级改写 model 名**;
- 第 2244 行附近:独立 task 承担上游读取 + **SSE 改写** + 结算;
- 第 117 行:流式响应预览抓取「改写后下发的 SSE 字节」。

监管口径里有一句关键表述:

> 如果在前端对 API 的输出做了二次处理——**内容过滤、重组、安全审核、格式优化**等——
> 可能被认定构成对模型的「实质性修改」,从而要求从**登记**升级为**备案**,
> 周期从 3~4 个月变成 6~8 个月。

本项目的改写是**协议适配(Anthropic ↔ OpenAI 格式互转)+ 模型名映射**,
属于工程必需,是否落入「实质性修改」存在解释空间。

**行动项**:提交登记前,先向属地省级网信办书面确认口径,不要等材料交上去才发现要重新走备案流程。

### 缺口 2:缺少服务协议与隐私政策

《生成式人工智能服务管理暂行办法》第九条明文:

> 提供者应当与注册其服务的生成式人工智能服务使用者签订**服务协议**,明确双方权利义务。

全仓库检索 `服务协议 / Terms / tos / privacy` **无任何命中**。这是低成本、可立刻补的一项。

另外同办法还要求:明确适用人群与用途、建立投诉举报入口并公布处理流程与反馈时限、
对使用者的输入信息与使用记录履行保护义务(不得非法留存可识别身份的输入信息)。

## 四、推荐路径:按规模分阶段

| 阶段 | 特征 | 该做什么 | 不该做什么 |
|---|---|---|---|
| **现在**(试水) | 个人身份、境外部署、月流水 < 1 万 | ① 注册一人有限责任公司(注册资本认缴,3~7 个工作日) ② 补服务协议 + 隐私政策 + 投诉入口 ③ 上线 BYOK(5% 抽成) ④ 用已有 `user_groups` 字段做能力分层 | 不做公开大规模推广;不碰账号池/逆向;不拆单绕过限额 |
| **有主体后** | 拿到营业执照 | ① 生成式服务登记(省级网信办,1~2 个月) ② 生成合成类算法备案 ③ 与网信办确认响应改写的定性 | 不要先上线公开收费再补登记(无锡案例的教训) |
| **月流水 > 5 万 或 开始对公销售** | 有 B 端客户、要发票 | ① 补 ICP 经营许可证(注册资本 ≥100 万 + 3 名人员社保 + 场地 + 技术方案) ② 团队席位/RBAC/审计/对公开票 | 不要在这个阶段还用个人身份收款 |
| **数据规模触发** | 累计 100 万人以上个人信息 | 数据出境安全评估申报 | — |

## 五、为什么 BYOK 在小规模阶段最优

1. **单位经济最好**:5% 抽成,零上游成本、零封号风险、不占资金池。
   OpenRouter 同款模式——BYOK 超出免费额度后收 5%。
2. **合规定性更轻**:用户自带 key,收取的是**技术服务费**而非转售差价,
   与「经营性互联网信息服务」的转售性质争议更小(但仍属生成式 AI 服务提供者,登记义务不免除)。
3. **客户匹配**:小团队往往已经有官方 key,痛点不是买 token,而是
   多模型统一路由、失败重试、用量可观测、账单归因——这些恰好是纯软件能力。
4. **与现有代码契合**:路由、重试、限流、语义缓存都已存在,不需要新的上游采购。

## 六、额度套餐的正确定位

保留,但**不作为利润来源**:

- 作用是降低试用门槛、把用户引进来(BYOK 对没有 key 的新手有门槛);
- 差异不要只堆额度(可比价,毛利锁死 22%),要挪到
  `max_concurrency` / `rpm_limit` / `tpm_limit` / 优先级 / 缓存是否计费 这些官方没有标价的维度;
- 这些字段 `user_groups` 表**已经存在**,几乎不需要新开发,改的是定价表达。

---

## 七、明确不能碰的三条

1. **账号池 / 逆向接口** —— 已有刑事案例(上海一站长因「反向代理 + 账号池」涉嫌非法经营罪被刑拘)。
2. **掺水换模型** —— 德国 CISPA 实测 45.8% 的影子 API 端点货不对板,行业正在被出清,
   且涉虚假宣传/欺诈风险。
3. **拆单或反复支付绕过限额** —— 爱猹收文档明确禁止,属违规操作。
