# 前端请求链路面板（RequestLogPanel）

## Summary

在管理后台新增"请求链路"面板，展示每次请求的路由候选顺序、负载均衡权重、failover 轨迹、最终结果与 tokens。

## 后端 API（已完成）

```
GET /admin/api/request-logs?q=&limit=50
```

响应格式：

## 改动清单

### 1. api.ts — 类型 + 请求方法

```typescript
// 新增类型
export interface RequestAttempt {
  kind: string;
  base_url: string;
  upstream_model: string;
  weight: number;
  status: number;   // 200=成功, 503=不可用, -1=熔断跳过, 400=错误
  latency_ms: number;
  error: string;
}

export interface RequestLogRow {
  request_id: string;
  user_id: string;
  path: string;
  requested_model: string;
  stream: boolean;
  candidates: RequestAttempt[];
  attempts: RequestAttempt[];
  final_kind: string | null;
  final_upstream_model: string | null;
  final_status: number;
  latency_ms: number;
  input_tokens: number;
  output_tokens: number;
  charged_tokens: number;
  ts: number;
}

// 新增 api 方法
requestLogs: (q?: string, limit?: number): Promise<{ data: RequestLogRow[] }> =>
  req(`/admin/api/request-logs?${new URLSearchParams({ q: q || "", limit: String(limit ?? 50) }).toString()}`)
```

### 4. App.tsx — RequestLogPanel 组件

**结构（列表型面板 + 行展开详情）：**

```
┌─────────────────────────────────────────────┐
│ 请求链路(128)  [搜索框________] [每页 50 ▼] │
├─────────────────────────────────────────────┤
│ 时间 | 用户 | 模型 | 路径 | 最终上游 | 状态 │
│ 14:32 | 张三 | gpt-4 | chat | openai | 200 │
│ 14:31 | 李四 | claude | msg  | anthropic|200│
│ 14:30 | 王五 | gpt-4 | chat | ❌ 503    │
├─────────────────────────────────────────────┤
│ ▼ 展开详情（点击行展开）                    │
│ ┌─── 候选顺序（负载策略）──────────────────┐ │
│ │ #1 openai  gpt-4   weight=100  → 200 ✓  │ │
│ │ #2 anthropic claude weight=100  (未尝试) │ │
│ └──────────────────────────────────────────┘ │
│ ┌─── 实际尝试（failover 链）──────────────┐ │
│ │ openai gpt-4  200  42ms  成功            │ │
│ └──────────────────────────────────────────┘ │
│ Tokens: IN 12 / OUT 88  延迟: 42ms          │
└─────────────────────────────────────────────┘
```

**核心逻辑：**
- **搜索框**：debounce 500ms → 调 `api.requestLogs(q, 50)`
- **列表**：时间(格式化 ts)、用户ID(截断)、模型名、path badge、最终上游、状态 Badge(200 绿/4xx 黄/5xx 红)
- **行展开**：点击切换展开状态，显示：
  - `candidates` 表格（候选顺序 + 权重 + 状态标记：✓成功 / -跳过 / ?未尝试）
  - `attempts` 表格（failover 链：kind + model + status + latency + error）
  - Tokens 汇总（input/output/charged）+ 总延迟
- **失败行高亮**：`final_status != 200` 时行用 `bg-rose-500/[0.04]`（与 FailureAudit 风格一致）
- **空态**：loading 态 → 无数据提示 → 正常表格
- **刷新**：useEffect 自动加载 + 搜索触发

**状态管理：**
```typescript
const [rows, setRows] = useState<RequestLogRow[]>([]);
const [q, setQ] = useState("");
const [loading, setLoading] = useState(true);
const [expanded, setExpanded] = useState<string | null>(null); // request_id
```

## Assumptions
- 遵循现有单文件模式（App.tsx 内联 RequestLogPanel）
- 表格用现有 Table/Card/Badge UI 原语
- 行展开不用 Dialog，直接在行下方插入详情区块（accordion 风格，与 UpstreamsPanel 的失败审计类似）
- 用户暂不显示用户名（只有 user_id），因为后端没有 JOIN users 表的请求接口——先截断显示 UUID 前 8 位

2. 发送请求（成功/失败）→ 刷新列表确认新数据出现
3. 点击行展开 → 候选权重表 + failover 链正确
4. 失败行红色高亮
5. Console 无错误
